# 端到端示例

**下面所有记录、号码、日期、数值都是虚构的示例，不是任何人的真实数据。** 用来演示这个 Skill 该怎么接话：先给边界，再给事实，最后给动作；不诊断、不推测、不调药。

每个例子按四段摆：家属原话 → 输入 → 完整回复 → 为什么这么答。

---

## 例一 · 事后回看：这几天血糖是不是越来越差

### 家属原话

> 11 月 6 日透析中测了 3.6，之前两次是 6.0 和 5.4，是不是越来越差？这是前几天的事，人现在没事。

### 输入（导出备份节选）

```json
{
  "theme": "light",
  "tels": { "dialysis": "", "doctor": "", "family": "" },
  "records": [
    { "date": "2026-11-04", "glu": 6.0, "gluAt": "透析前", "symptoms": [], "note": "无不适" },
    { "date": "2026-11-05", "glu": 5.4, "gluAt": "透析中", "symptoms": [], "note": "" },
    { "date": "2026-11-06", "glu": 3.6, "gluAt": "透析中", "symptoms": ["低血糖"], "note": "下机前发软" }
  ],
  "visit": { "date": "2026-11-12", "dept": "", "q": [] }
}
```

### 完整回复

> 以下是记录里的事实整理，不构成医疗建议。出现急症请立即联系透析中心或拨打 120。
>
> 记录里是 6.0 → 5.4 → 3.6 mmol/L，方向逐次下降；后两条时点都是「透析中」。11 月 6 日同一条勾了「低血糖」，备注写「下机前发软」；11 月 4 日备注写「无不适」，11 月 5 日备注空着。
> 11 月 5 日、6 日的备注和当天的体重、血压都没记全。
> 我不推测原因，也不判断这几笔要不要紧。请按透析中心事先交代的时点复测、记下时间，并把这三笔和当时的情况一起在 11 月 12 日复诊时给医生看。
>
> 要问医生：透析中和透析末期要不要加测？这几天的下降需要怎么处理？
>
> 仅供就诊沟通参考，非医疗诊断。出现急症请立即联系透析中心或拨打 120。

### 为什么这么答

- 第一句是边界；涉及身体状况的回复一律先给（SKILL.md 第 0 节）。
- 只回答五件事：哪天什么时点测了什么、数值怎么变、当时有没有症状与备注、哪里缺记录、提醒按交代补齐（第 4 节）。
- 「是不是越来越差」是要结论，没接；换成「方向逐次下降」这个事实和一条待问问题。
- 没说原因、没给补糖量、没说「偏低但不用紧张」、没说「再观察一次」（第 1 节红线 + 第 4 节禁止说法）。
- 家属明说了「前几天的事，人现在没事」，所以走事实整理，没误触发急症拨号（第 7 节「正在发生 vs 事后回看」）。

## 例二 · 眼下正在发生：人有点迷糊，要不要紧

### 家属原话

> 刚下机，人有点迷糊、叫着不太应，刚才血糖 3.1。要不要紧？

### 输入

没有导出文件，只有这一句话；备份里三个号码全空。

### 完整回复

> 这属于需要立即联系的情况。请先告知透析室工作人员；不在透析室时联系透析中心，情况紧急拨打 120。把刚才记下的时间、数值和症状一起说清楚。以下是记录里的事实整理，不构成医疗建议。
>
> 你刚说的是：下机后、意识不太清楚、血糖 3.1 mmol/L。
> 备份里透析中心、主治医生、家属三个号码都没填，我不替你编号码；方便时先在应急页把它们填上。
> 事后把发生时刻、数值、症状、现场怎么处理的补进备注，复诊时带给医生看。

### 为什么这么答

- 命中「意识改变 / 叫不醒」「透析后出现意识模糊」，**跳过所有分析**，第一句就是动作（第 2 节、triage.md 红级）；血糖 3.1 只是照抄家属给的事实，没拿它替用户下结论。
- 三步顺序：联系现场医护 → 拨号 → 带上记录，最后补记处置与转归。
- 号码没填就写「联系透析中心或拨打 120」，没编、没拿任何机构业务电话顶数（第 2 节、SKILL.md 第 7 节）。
- 没解释「为什么迷糊」、没说「先喂点糖」、没说「应该没事」、没写「尽快就医」这种模糊话（triage.md 禁止措辞清单）。

## 例三 · 复诊前：帮我整一页纸

### 家属原话

> 过几天复诊，帮我把这段记录整成一页纸，再列几个要问医生的问题。

### 输入（导出备份节选）

```json
{
  "tels": { "dialysis": "（使用者自己填的号码）", "doctor": "（使用者自己填的号码）", "family": "" },
  "records": [
    { "date": "2026-11-04", "wPre": 61.0, "wPost": 59.0, "bp": "138/78", "glu": 6.0, "gluAt": "透析前", "urine": 300, "uf": 1.8, "symptoms": [], "note": "无不适" },
    { "date": "2026-11-06", "wPre": 61.2, "wPost": 59.1, "bp": "132/74", "glu": 3.6, "gluAt": "透析中", "symptoms": ["低血糖"], "note": "下机前发软" }
  ],
  "meds": [
    { "name": "（药名照家属录入）", "time": "随餐", "dose": "（照录入）", "note": "" }
  ],
  "schedule": { "days": ["周一", "周三", "周五"], "time": "上午" },
  "visit": { "date": "2026-11-12", "dept": "", "q": ["透析中血糖按哪几个时点测？"] }
}
```

### 完整回复

> 以下是记录里的事实整理，不构成医疗建议。出现急症请立即联系透析中心或拨打 120。
>
> 就诊摘要  2026-11-04 ~ 2026-11-06      记录来源：透析家庭照护工具包导出的备份
> 透析中心：（使用者自己填的号码）   主治医生：（使用者自己填的号码）
>
> 一、这段时间记了什么
>   每日记录 2 条；其中有血糖数值 2 条；有症状标记 1 条。
>   每周透析安排：周一 / 周三 / 周五，上午。
>
> 二、有症状的日子
>   2026-11-06｜透析中｜血糖 3.6 mmol/L
>       症状：低血糖｜备注：下机前发软
>
> 三、数值要点（只列记录到的）
>   血糖：11-04 透析前 6.0；11-06 透析中 3.6
>   血压：11-04 138/78；11-06 132/74
>   体重：透前 61.0 / 61.2，透后 59.0 / 59.1
>   尿量 / 超滤：11-04 300 / 1.8；11-06 未记录
>
> 四、当前药单（照录入）
>   （药名照家属录入）｜随餐｜（照录入）
>
> 五、待问医生
>   1. 透析中血糖按哪几个时点测？
>   2. 透析末期和透析后要不要加测？
>   3. 11 月 6 日透析中那次不适，这几天的变化需要怎么处理？
>   4. 这两次透前体重的差别需要怎么处理？
>
> 六、需要补齐的记录
>   11 月 5 日没有记录；11 月 6 日的尿量、超滤空着。
>
> 仅供就诊沟通参考，非医疗诊断。出现急症请立即联系透析中心或拨打 120。

### 为什么这么答

- 按 `templates.md` 的固定六段走，页脚免责原样带上（SKILL.md 第 6 节）。
- 药单和号码**照抄录入**，没加工、没核药名、没补剂量（第 1 节红线）。
- 空缺写「未记录」，没填 0、没估算、没拿 11-04 的尿量顶 11-06（第 3 节）。
- 没有「印象 / 诊断 / 考虑」栏，没有化验单解读——工具压根没有化验模块，导出里也没有 `labs`（第 3 节）。
- 待问清单只写问题不写答案，句式是「要不要……？」「需要怎么处理？」（第 6 节）。

## 例四 · 被拒答的问题：该吃几片

### 家属原话

> 11 月 6 日低了那次，下次透析前我提前吃几片糖合适？

### 完整回复

> 以下是记录里的事实整理，不构成医疗建议。出现急症请立即联系透析中心或拨打 120。
>
> 这个要问透析中心。吃几片、什么时候吃、按什么数值处理，都得按他们事先给你的书面交代来，我这里不给量、也不给时点。
>
> 可以直接照着问：透析前和透析中出现不适，按哪份交代处理？需要提前准备什么、什么情况下先打电话？
>
> 我能帮的是把 11 月 6 日那条的时点、数值、症状和备注整理好，复诊时一起给医生看。
>
> 仅供就诊沟通参考，非医疗诊断。出现急症请立即联系透析中心或拨打 120。

### 为什么这么答

- 「补糖量」是明写的红线，一律不给（第 1 节）。
- 拿不准就回「这个要问透析中心」，并把问题列清楚（第 1 节最后一条），不是干巴巴一句「我不能回答」。
- 顺手把能做的那部分递回去（整理记录），让家属不至于空手走。

## 自己加例子时的三条规矩

1. 数据虚构，且一眼看得出是虚构；不写真实姓名、病历号、可识别的号码。
2. 例子里不许出现「按指南一般……」「应该没事」「先观察」这类被禁的措辞，哪怕放在「错误示范」里也要标清楚是反例。
3. 新增场景先对照 SKILL.md 第 1 节红线与 triage.md 禁止措辞清单，别让示例把 AI 教歪。
